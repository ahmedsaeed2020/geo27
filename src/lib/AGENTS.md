## src/lib rules
- Record history uses the Framework `Version` DocType shape in the adapter, so activity timelines read the same records every view uses.
- Number cards and charts compute from adapter records at render time; never store dashboard totals separately.
- Data Import/Export run client-side in src/lib/dataImport.ts over the adapter (template headers = field labels, child columns 'Label (Table)'), so imported rows appear in every view immediately.
- List layouts (src/lib/listLayouts.ts) are derived generically from meta + list indicator rules and selected via the `layout` URL param, so layouts stay shareable and source-driven.
- Shell-level demo records (Notification Log, Event, GL Entry derived from submitted vouchers) are seeded in seed.ts after seedDemo, so ledger rows always match the demo vouchers.
- Value display (currency, numbers, dates) goes through src/lib/format.ts (System Settings defaults), so form, child grid and list cells format identically.
- SAR amounts render as the official Riyal sign U+20C1 (bundled "DIGIT Riyal" font, LTR-isolated, sign left of the number) via format.ts fmtCurrency/riyal; text that leaves the screen (CSV, print text, clipboard) goes through plainMoney/fmtCurrencyPlain and keeps "SAR", so stored data and exports never carry the glyph.
- Catalog definitions get DocPerm.permlevel (src/lib/sourcePermlevels.json) and the other lost DocPerm flags — amend, print, email, share, report, export, import, select, if_owner (src/lib/sourcePermFlags.json) — restored when cached in catalog.ts (both from scripts/extract-permlevels.py over public/catalog/raw), because the frozen catalog rows lost them: a level-1 or owner-only rule must never grant document access, and no native right may be missing.
- Seed display names are Arabic-first via src/lib/seedNamesAr.ts (one-time migration of __synthetic records only), so user records are never rewritten.
- Renames go through src/lib/rename.ts (rename_doc with merge + value cascade, persisted rename log); seed skips renamed names and hard-coded defaults resolve via resolveName, so renamed masters are never re-created.
- Return documents are validated by returnErrors() in src/lib/posting.ts (port of validate_returned_items) on submit, so no return exceeds its original.
- Number Card/Chart filters (src/lib/desk.ts matchFilter) treat unset Check/Int as 0 and evaluate Timespan against today, matching frappe.utils, so card values follow source semantics.
- Workflows run only through src/lib/workflow.ts (transitions by role, allow_edit, docstatus via posting.ts), so states and ledger stay consistent.
- Asset depreciation, sale/scrap and restore run in src/lib/assets.ts and post only via Journal Entries submitted by posting.ts, so asset GL follows the shared posting engine.
- Asset Movement/Repair/Capitalization controllers live in src/lib/assetDocs.ts as adapter doc hooks (submit/cancel), registered from seed.ts, so every screen runs the same on_submit/on_cancel logic.
- Bank Transaction/Bank Clearance/Payment Reconciliation logic lives in src/lib/reconciliation.ts; ledger relinking goes only through posting.ts reconcileAllocations, so outstanding stays ledger-derived.
- Budget control (Stop/Warn on JE, Purchase Invoice, Purchase Order, Material Request) lives in src/lib/budget.ts and is called from posting.ts submitErrors, so every submit path applies one budget rule; GL Entry rows carry line-level cost_center/project for budget actuals.
- Opening Invoice Creation Tool (make_invoices) lives in src/lib/openingInvoices.ts and submits invoices via posting.ts; source set_primary_action buttons are listed in localActions.ts LOCAL_PRIMARY.
- Accounting Dimensions live in src/lib/dimensions.ts (Custom Field records per dimension, rowDims on GL lines, dimensionErrors on submit, dimFilterOk in reportRunner gle), so forms, ledger and reports share one dimension set.
- Deferred revenue/expense live in src/lib/deferred.ts: invoice rows post to the deferred account in posting.ts glLines; recognitions are stored on the submitted Process Deferred Accounting doc (entries) and posted by posting.ts (own GL or Journal Entries per Accounts Settings), so booked amounts are read from one record set and reprocessing is idempotent.
- Posting locks come only from Company accounts_frozen_till_date and Accounting Period closed documents (posting.ts lockErrors); a Period Closing Voucher never blocks later postings, matching ERPNext.
- Selling/buying cycle limits (over-delivery/billing allowance, credit limit, expired quotation, zero qty, cancel back links) live in src/lib/selling.ts and are called from posting.ts submit/cancel, so every screen and test hits the same checks.
- Stock rules (purpose checks, negative stock, Stock Reconciliation absolute qty/value in repost, Landed Cost distribution) live in src/lib/stock.ts; posting.ts calls them and passes repost in, so stock.ts never imports posting.ts.
- Serial No / Batch No (row serial_no/batch_no fields) live in src/lib/serialBatch.ts; posting.ts calls its checks and state updates on submit/cancel and batch balances derive from submitted voucher rows, so every stock document shares one rule set.
- Department form buttons are local actions in src/lib/localActions.ts (LOCAL_ACTIONS + LOCAL_WHEN eligibility, falling back to the source button conditions so a ported button never shows where the source form hides it, + LOCAL_EXTRA for buttons absent from source JS) calling departments.ts/posting.ts; salary accrual is one Payroll Entry Journal Entry (departments.ts submitPayrollSlips), never a Salary Slip GL, so payroll matches HRMS make_accrual_jv_entry.
- ERPNext CRM hand-off (Lead/Opportunity status from Quotation, Sales Order, Customer) lives in src/lib/crmHandoff.ts, called from posting.ts after submit/cancel, so standalone Frappe CRM stays separate.
- Document reads/writes for generic screens go through src/lib/documentApi.ts (createDraft/saveDocument/submit/cancel/amend over the adapter, posting.ts and session.ts); a new document is a local `new-…` draft tagged with its browser tab (`__tab`) and its autoname is resolved on first save, so abandoned drafts never consume series numbers and another tab's open draft survives a new Add.
- `adapter.list` returns saved records only; unsaved `__islocal` drafts appear only with `{ includeLocal: true }`, so lists, counts, reports and engines never see a document that frappe still holds in page locals.
- Lifecycle availability comes from src/lib/runtimeContract.ts classifyDocument over generated public/source-intelligence/runtime-contract.json (exact controller-class evidence + local virtual rules); unknown or unported controllers default to SERVER_ONLY, so the preview never claims Frappe controller behaviour.
- Field controls are declared once in src/lib/fieldTypes.ts (every frozen fieldtype explicit: editable, limited, display, layout, table or read-only), so FormView, the SDK explorer and fit-gap share one support matrix.
- Action, settings, domain, report and effective-meta registries (actionRegistry.ts, settingsRegistry.ts, domainMaps.ts, reportRegistry.ts, metaResolver.ts) are read-only compositions of generated source intelligence and existing engines; they never store business records or invent effects.
- User defaults are resolved only by src/lib/sessionDefaults.ts (resolveUserDefault/defaultCompany/newDocLinkDefaults/filterDefaultFromExpr, ports of frappe defaults + create_new.js) and user preferences only by userSettings.ts, both keyed per simulated user, so forms, reports and settings read one permission-checked value and users never share defaults.
- New documents and child rows take values only from sessionDefaults.newDocDefaults through documentApi.createDraft / newChildRow (port of create_new.js set_default_values, add_child, create_mandatory_children), plus — for a form dashboard "+" — documentApi.linkFieldValues (port of form.js set_link_field); no screen invents field values or rows, so stored records hold only user input and source defaults.
- Deletes go only through src/lib/deleteDoc.ts (delete_doc port: capability-graph link checks, ported on_trash/after_delete, SERVER_ONLY for unported business hooks, Deleted Document tombstones that seeds honour via deletedDocs.ts), so form and list deletes apply one rule set and deleted seed rows never return.
- List menu and bulk actions are gated by src/lib/listActions.ts (list_view.js / bulk_operations.js rules) and run through bulkOps.ts and assignment.ts over documentApi/posting.ts, so bulk paths hit the same permission, workflow and lifecycle checks as a single form.
- Module sidebars with no workspace (or an empty develop workspace) open their first resolvable sidebar link via desk.ts firstSidebarRoute (port of frappe.utils.get_route_for_icon), so no module entry renders a blank page.
- Department homes use departmentHomes.ts and scoped records; KPI/queue drills share desk.matchFilter. Finance dates: Bank Transaction.date, otherwise posting_date.
- Customize Form (/customize-form) saves only as Property Setter / Custom Field records diffed against the frozen catalog meta (field order = DocType-level field_order setter), so customizations stay additive and exportable.
- Department lifecycle rules (HRMS, Projects, Manufacturing, Quality, Support) live in src/lib/departments.ts and are called only from posting.ts submit/cancel, so every screen shares one lifecycle.
- Home/bell activity rules live in activityFeed.ts: Recent changes skip setup Version rows (`__setup`, or creation rows of `__synthetic` records) and Arabic notification/event subjects are display-only (`subject_ar` or structured templates), so sample data never poses as user activity and stored text stays unchanged.
- Rich sample data (src/lib/volume, app providers via registerVolumeProvider) is inserted inside adapter.ephemeral() after the standard seeds: memory only, never persisted, insert-if-missing, vouchers posted by posting.ts postVouchers, so it fills screens without changing stored data or the 5 MB storage budget.
- DIGIT Assistant: model calls happen only in the /api/assistant server route (src/lib/ai, key read inside the handler); its tools are declared in src/lib/assistant/protocol.ts and executed in the browser through scope.ts, read-only, so answers never exceed the simulated user's permissions and nothing is written.
- Site sign-in gate: the root route beforeLoad requires the server-verified httpOnly cookie from src/lib/siteAuth.functions.ts (only /login and /api/* are open); credentials live only in that server module, so the gate cannot be bypassed from browser storage. The simulated ERP Switch User session is separate.
- Related-document counts (form Connections, Document 360) come only from src/lib/relations.ts (ports of frappe get_open_count / get_filter child-table resolution / get_internal_links, Dynamic Link type pairing), permission-scoped, with "limited" derived from the user's own rules via scope.ts readLimitedFor — never from hidden rows — so every surface counts the same records and reveals nothing.
- Dashboard customization is one Core mechanism (src/lib/dashboards: views.ts shape→view compatibility, registry.ts app-registered widget contracts, layout.ts versioned layouts personal → role template → global → app default, re-validated against the current contract); apps own widget meaning/data/original renderer and the Core never stores figures, so every app's dashboards share one editor, precedence and permission rule.
- Document Hub classification (src/lib/hub.ts) derives groups from catalog metadata; an explicit group declared by a later duplicate (native Setup card, setup list) wins over inference, and child tables / uninstalled targets are dropped with a reason, so hubs never show decorative links.
- Site session checks (root and /login beforeLoad) call getSiteSession through siteGate.ts withNetworkRetry, which retries only requests that never reached the server, so a server restart or network drop does not blank the page while the gate still never opens on a failure.
- Outdated code-split files after an update are recovered only by staleChunk.ts (root errorComponent + vite:preloadError/unhandledrejection listeners from __root): one reload per failing file per 30 s, so a later update reloads again while a truly missing file shows the error screen instead of looping.
- Stock Entry item rows are checked on save by src/lib/stockEntryRows.ts (active stock Item, positive qty, Item-sourced details only; placeholder rows judged on in_list_view columns), so generated hidden-field rules never make a blank row count as entered.
- Exchange gain/loss on foreign-currency payments is booked only by coreShared/exchangeDiff.ts (an "Exchange Gain Or Loss" Journal Entry linked by digit_against_payment), and posting.ts keeps party ledger lines in the party account currency, so a foreign-currency invoice settles in its own currency and the difference lands once.
- Form titles taken from a Select option or a Link to a source translated_doctype (src/lib/translatedDoctypes.json, generated by scripts/extract-translated-doctypes.py over public/catalog/raw) are displayed through translateTo via src/lib/titleDisplay.ts, so Arabic screens read the label while stored values stay as in source.
- Scheduled report e-mail (Auto Email Report Download / Send Now local actions) runs in src/lib/autoEmailReport.ts over reportRunner RUNNERS, session filterReportRows and providers.queueEmail, so the mailed rows equal the report screen and delivery status comes only from the e-mail provider.
- Print templates read linked rows with frappe.get_list (scope.ts readable rows narrowed by app rules from registerPrintListScope; get_all stays unrestricted as in Frappe) and the printed document drops fields at unreadable permission levels (printEngine readableFields), so a print never shows more than the form.
- Dates display dd/mm/yyyy and chart months «أكت 2026» / «Oct 2026» through src/i18n/dates.ts (fmtDay/fmtMonth and a display-only DOM pass), format.ts fmtDate and form/DateInput; stored values stay ISO, so every screen reads one date format without changing data.
- Shared saved views are List Filter records owned by src/lib/sharedViews.ts (private / team / all / custom, 20 per owner and DocType, owner-only edit and delete, team from the app's setTeamResolver) and trail verbs come only from approvalPath.ts actionVerb / moveVerb, so hubs, lists and every trail share one rule.
- Bank reconciliation position (statement − cleared = difference, 12-month bank / close strips, close checks) is read only from src/lib/coreShared/bankRecon.ts over the native Bank Reconciliation Statement runner, so every page shows one difference.
- Item picks on selling/buying rows are filled only by src/lib/itemDetails.ts (port of get_item_details: names, unit/conversion, Item Price, item tax template, accounts; default/selected tax template rows), called from formRules.ts applyChange before row rules, so every generic form fills items one way and totals stay in formCalc.ts.
