- Preview-only notes use <DevOnly> (DevOnly.tsx), never inline useDevMode() inside conditions, so hook order stays stable.
- Phones (<768px) get the dock and module sidebar from Shell.tsx's off-canvas menu (backdrop, closes on navigation) while the desktop show/hide preference stays in userSettings, so one navigation tree serves both sizes.
- Child table grids live in form/ChildGrid.tsx with per-child-DocType column config, so every form's tables share one implementation.
- Report cells that point at documents go through report/DocPreview.tsx (ReportPreviewScope + ReportDocLink) with lib/reportLinks.ts reportCellTarget (Link/Dynamic Link only, summary rows inert), so every report shares one read-only, permission-checked preview that keeps the active app.
- Workspace blocks use the .ws-block class (styles.css): source column width from sm up, stacked on phones (number cards two per row), so source layouts never overflow a phone.
- Workspace/widget diagnostics (source paths, missing card/chart definitions, chart type, preview notes, server reasons) render only inside <DevOnly>; users see the plain 'Needs the Frappe server' / 'Not permitted' label.
- Native Frappe CRM screens live under `src/routes/crm.*` + `src/components/crm/`, driven by source layouts in `public/catalog/crm_layouts.json`; generic forms remain the labelled fallback, so native vs generic coverage stays explicit.
- Dedicated Frappe Desk Pages live in `src/components/pages/registry.tsx` (keyed by source Page name) and render at `/page/$name`; Desk sidebar/workspace links with link_type Page resolve through that registry, so page coverage stays traceable to source.
- Shared DIGIT inner-screen geometry lives in enterprise/enterprise.css inside `@layer components`, scoped to `html[data-enterprise]` (below utilities and every unlayered app sheet), so a screen's own classes and app styles always win and only the gaps take PES V1 values.
- Before hydration Shell.tsx renders neutral navigation placeholders (`data-shell-pending`), never the Core Desk launchers, because the browser's DIGIT/Core mode is only known after hydration.
- Enterprise app tiles (dock, Enterprise Home, nav) resolve through `appTile()` in enterprise/iconMap.ts: an app with its own tile artwork uses it, others place their official dark artwork on the shared brand tile, so all apps share one tile treatment without redrawn logos.
- The shared Dashboard Designer UI (dashboards/DashboardDesigner.tsx + dependency-free SVG views.tsx) and native Document Hub UI (hub/DocumentHub.tsx) are app-agnostic: apps pass contracts, links, permission states and URL state in, so no app logic or navigation leaks into the Core components.
- Form dashboard tabs (Connections) passed as FormView extraTabs render at the top of a source Tab Break with the same label, as frappe form/dashboard.js does, so a Custom Field an app adds to that tab never hides the related documents.
- The record route turns `/app/<app>/<doctype>/new` into a documentApi.createDraft draft (refusal shown), and list/form routes render DocTypeNotFound when a DocType definition is missing (metaQuery does not retry it), so Hub "+ New" links and unknown DocType URLs never end on "not found"/Loading.
- Same-screen opening of vouchers, parties, items, KPIs and list drills goes through enterprise/QuickView.tsx (openQuickView / QuickLink, one QuickViewHost in the Shell header, role read + User Permission checked), so every app shares one side panel / drawer / dialog.
- Enterprise and DIGIT Pro pages draw bands, KPI tiles and charts only with the shared kit (enterprise/kit: ContextStrip, KpiRow/KpiStrip/KPI_TILE, kit charts) and place page dashboards through dashboards/PageBlocks.tsx, enforced by src/test/closure/oneShell.closure.test.ts, so one look and one per-user/per-role customisation path cover every page.
- Every dashboard block carries its own menu (dashboards/BlockMenu.tsx: period, compare, view, size, move, remove) whose window is resolved by lib/dashboards/registry.ts blockWindow and saved per user with the layout, so the page filter bar is only the default.
- App headers render through ContextStrip (Experience CommandBand/DxIdentity, HR ModuleBand/HrCommandHeader, CRM CrmFrame/CommandHeader, ServiceRoute, ReportWorkbench, tree/settings bands) with section tabs placed under the band via BandTabsHost, ranked lists via kit/rank.tsx and posting documents show DocInsight EffectPreview, so one band, card and list standard covers every app.
- Shared service pages (enterprise/ServicePages.tsx ServiceRoute) open a band slot (enterprise/bandSlot.tsx); the shared FinanceDesk `Bar` portals the page's selectors and main action into it, and the page opens inside the app whose navigation places it (experience slot `corePage`: sidebar, eyebrow, tabs under the band), so Core pages inherit an app's frame without app code.
- Form Connections links and their "+" drafts carry the form's `?app=` context, so an app's address map (lib/appUrls.ts) shows them at the app's own address inside its frame, never a Desk address.
- Raw colours live only in enterprise/tokens.css (Phase 3 names; names that collide with the component library are published as --line / --quiet / --tone-*), and the visual layer enterprise/visual.css applies under `[data-visual="r3"]` (set by Shell for Enterprise and each app shell except CRM), enforced by src/test/visual/visualSystem.test.ts, so one palette serves every app and CRM keeps its own until its round.
- Every create panel / create drawer header carries enterprise/OpenFull.tsx OpenFullLink: the host keeps what was typed in the same `new-…` draft and opens the full form, so no quick-create ever traps the user in a short form.
- Link, Dynamic Link, child-row link and report link-filter inputs use form/LinkCombo.tsx (list under the field, code + readable name, keyboard, portalled into the open dialog when inside one) instead of <datalist>; callers pass already filtered/permitted options, so the control never decides what a user may pick.
- Enterprise kit display pieces, Document Hub register layout, chart rules and brand-band chips are in `src/components/enterprise/AGENTS.md`; read it before changing files there.
